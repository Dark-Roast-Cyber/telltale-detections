# `tdx.persistence.powershell_profile_write`

This candidate detects writes to a PowerShell profile requested through an agent tool call. The profile is `$PROFILE` (including its `.CurrentUserAllHosts`-style properties), `$PSHOME\profile.ps1`, or a `profile.ps1` / `Microsoft.<host>_profile.ps1` path under a `WindowsPowerShell` or `PowerShell` directory. A write is `Add-Content`, `Set-Content`, `Out-File`, or `Tee-Object` with the profile as the first argument or the `-Path`, `-LiteralPath`, or `-FilePath` value; a `>` or `>>` redirection into it; a `Copy-Item` or `Move-Item` whose `-Destination` is the profile, in any parameter order; or a `Copy-Item`, `Move-Item`, `cp`, `copy`, `mv`, or `move` with the profile as the second positional argument, after a source given positionally or with `-Path` / `-LiteralPath`. The profile must end the argument, so a backup name such as `$PROFILE.bak` or `Microsoft.PowerShell_profile.ps1.bak` is not a profile write. It evaluates the Rule v1 `command` and `arguments` fields, which prove the request, not the resulting file.

The core rule `persistence.shell_profile` covers Unix shell profiles, cron, `systemctl enable`, and `launchctl load`; it does not read PowerShell profiles. Severity is medium, score 45, the same score as that core rule: profile edits are common requested setup, and the rule alone stays below the default security-review threshold.

Reading or loading the profile does not match: `Get-Content $PROFILE`, `Test-Path $PROFILE`, `. $PROFILE`, printing `$PROFILE`, and opening it in an editor. Copying the profile elsewhere (including to a `.bak` name), redirecting its content to another file, and naming `$PROFILE` as a value written to another file do not match. The bounded window after a write cmdlet stops at a pipe, `;`, `&`, or line break, so `Get-Help Add-Content -Full; Get-Content -Path $PROFILE` does not match; in the serialized `arguments` field an escaped `\n` does not end the window. `New-Item -Path $PROFILE -ItemType File -Force`, the documented way to create an empty profile, does not match; the same command with `-Value` content is therefore not covered.

At the pinned revisions, both Codex `compatible` and OpenCode `upstream` record `detected` for `detection.windows_powershell_profile_write` (`Add-Content -Path $PROFILE`) and `clean` for `detection.windows_powershell_profile_backup`, `detection.windows_persistence_read_only_audit`, and `detection.windows_persistence_docs_search`. The redirection and copy forms are covered by pattern tests only.

Expected false positives are requested shell setup, such as a module import, alias, or prompt line, quoted command examples, and `-WhatIf` previews, which Rule v1 regexes cannot exclude. Not covered: edits through an editor or a native file-writing tool, profile paths held in another variable, and `New-Item -Value`.
