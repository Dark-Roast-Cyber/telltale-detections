# `tdx.persistence.windows_service_change`

This candidate detects Windows service persistence requested through an agent tool call: `New-Service` with a `-Name` or `-BinaryPathName` argument, `sc.exe create` or `sc.exe config` with `binPath=` or an automatic `start=` value, and `Set-Service` with `-StartupType Automatic` (including `AutomaticDelayedStart`). It evaluates the Rule v1 `command` and `arguments` fields. Those fields prove that the agent requested the change; they do not prove that the service controller accepted it or that the service ran.

Telltale core rules have no Windows service rule. The process-chain pack infers service creation from command text and is a separate opt-in; this rule does not depend on it. `tdx.persistence.windows_agent_command` covers scheduled tasks, autorun keys, and the Startup folder, so a single command does not match both rules.

The rule needs service arguments, not only a cmdlet name: `Get-Help New-Service`, a documentation search for `New-Service|sc create`, `sc query`, `sc qc`, and `Get-Service` do not match. Disabling a service (`start= disabled`, `-StartupType Disabled`) and changing only its status do not match. In PowerShell, `sc` is an alias for `Set-Content`; `sc config.json ...` does not match because the rule needs a service name and a `binPath=` or `start=` argument after `create` or `config`.

At the pinned revisions, both Codex `compatible` and OpenCode `upstream` record `detected` for `detection.windows_service_create` (`sc.exe create` with `binPath=` and `start= auto`) and `clean` for `detection.windows_requested_service_disable`, `detection.windows_persistence_read_only_audit`, and `detection.windows_persistence_docs_search`. The `New-Service` and `Set-Service` forms are covered by pattern tests only.

Expected false positives are requested software installs and administration that create a service or enable automatic start, and quoted command examples that include service arguments. Not covered: service creation through the registry (`HKLM\SYSTEM\CurrentControlSet\Services`), installers, `InstallUtil`, `New-CimInstance Win32_Service`, scripts whose contents are not in the searchable arguments, and `sc config` changes to the service account or failure actions.
