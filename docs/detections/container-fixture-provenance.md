# Container host-access fixture provenance

The `container-host-escape.yaml` scenarios use **synthetic session records** with commands adapted from documented CLI/API syntax and published research. They are not captured Telltale telemetry, real execution logs, live exploitation, or proof that a sandbox boundary was crossed. `shell`, `write_file`, and `SYNTHETIC_CONTAINER_ID` are lab-level modeling placeholders, not verbatim vendor session records.

## Source-to-fixture mapping

| Scenario | Primary evidence | Adaptation and preconditions | What it proves |
| --- | --- | --- | --- |
| `docker_desktop_virtiofs_escape.json` | [Pillar Security, July 20 2026](https://www.pillar.security/blog/one-docker-socket-to-rule-them-all-escaping-codex-cursor-and-gemini-clis-sandboxes), reproduced chain using `docker run --privileged` and `docker exec ... mkdir -p ... && mount -t virtiofs virtiofs0` | Simplified to the documented Docker sub-chain with an Alpine image assumed available. Requires Docker Desktop macOS, accessible Docker daemon, suitable virtualization and a virtiofs0 share. Not every Docker host exposes this tag. | A *command request* for the published host-share access primitive, not a completed escape |
| `docker_socket_host_root_mount.json` | [Docker bind mounts](https://docs.docker.com/engine/storage/bind-mounts/) and [Sysdig, June 4 2026](https://www.sysdig.com/blog/agentic-threat-actor-hits-the-orchestration-plane-ai-agent-driven-container-escape) | Uses supported `docker run -v /:/host:ro` and an actual Alpine image tag; assumes a Linux daemon with permission to mount the root path. On Docker Desktop, `/` can refer to the VM rather than the macOS host. | A requested host-root **read-only bind**, not proof of file reads or exfiltration |
| `docker_api_privileged_create.json` | [Moby Engine API create reference](https://github.com/moby/moby/blob/master/api/docs/v1.24.md#create-a-container) and [Sysdig's observed Docker API create request](https://www.sysdig.com/blog/agentic-threat-actor-hits-the-orchestration-plane-ai-agent-driven-container-escape) | Contains actual Docker fields `Image`, `Cmd`, and `HostConfig.{Binds,Privileged,PidMode,NetworkMode,IpcMode}`. Replaces Sysdig's host-secret reads with a harmless directory list and uses an Alpine image assumed present locally. The response ID is explicitly synthetic. | The API create **request** can be detected; create alone does not start the container |
| `testcontainers_socket_mount.json` | [Testcontainers/moby-ryuk README](https://github.com/testcontainers/moby-ryuk/blob/main/README.md#usage) | Maintainer's Docker socket and port 8080 launch, adapted to detached mode with a loopback port binding. The image is the real `testcontainers/ryuk:latest`. | A legitimate socket-mount **hunt-only** example; no host root bind |
| `node_exporter_host_monitoring.json` | [Prometheus node_exporter README, Docker usage](https://github.com/prometheus/node_exporter#docker) | Maintainer's exact host PID, host networking, read-only root mount, and `--path.rootfs=/host` shape. Image is real `quay.io/prometheus/node-exporter:latest`. | An **authorized benign command that triggers the host-access alert**; retain as an expected false-positive finding |
| `container_docs_search.json` | `rg -n` standard read-only ripgrep usage; see [ripgrep project](https://github.com/BurntSushi/ripgrep) | Documents and output are synthetic; only the read-only search command is evaluated. No filesystems are mounted. | A negative test for quoted tokens that resemble an escape command |
| `compose_privileged_file_write.json` | [Docker Compose services specification](https://docs.docker.com/reference/compose-file/services/) and [Compose trust model](https://docs.docker.com/compose/trust-model/) | `privileged: true` and `volumes: - /:/host` are valid fields. The `write_file` action is modeled, not executed, and no `docker compose up` follows. | A **visibility limit**, not a detectable executed escape in current Rule v1 targets |

The `nsenter --target 1 --mount --uts --net --pid -- ...` regression-test command is independently supported by the [util-linux `nsenter` manual](https://man7.org/linux/man-pages/man1/nsenter.1.html) and [Sysdig's observed fallback](https://www.sysdig.com/blog/agentic-threat-actor-hits-the-orchestration-plane-ai-agent-driven-container-escape). PID 1 belongs to the namespace visible to the command; it is not always host PID 1.

## Review boundaries

- **Behavior and causality:** A match establishes that an agent requested a command containing specified syntax. It does not establish daemon connectivity, successful execution, mount completion, file access or actual malicious intent.
- **Synthetic result fields:** The lab generates `status`, `exit_code`, and `output` as simulation data. `SYNTHETIC_CONTAINER_ID` is not a valid observed container ID and intentionally must not be treated as one. These output fields are **not** what the two Rule v1 regexes detect.
- **Environment:** Docker host filesystem, socket and namespace behavior vary between native Linux, rootless Docker, Docker Desktop VM, macOS, and Windows. Only the documented platform-specific assumptions support a fixture.
- **Known false positives:** The official node_exporter case triggers the high-severity rule even when authorized. Its independent `no_alert` label must remain intact, and the assessment should report the false positive. Neither the rule's high severity nor synthetic aggregate counts validate production precision.
- **Lab limitations:** These fixtures do not execute Docker, fetch images, or run the native application harnesses. The pinned Codex/OpenCode assessment validates parser-to-event-to-rule behavior only for those generated formats. Real-session captures and platform-specific end-to-end reproductions remain separate work.

## Regression contract

`tests/test_container_host_escape.py` validates that the Docker API fixture contains a parseable create payload with the documented essential fields, that VirtioFS mounts are preceded by `mkdir -p`, that Ryuk uses the real upstream image and documented socket mapping, that the Compose fields remain present, and that the official node_exporter launch remains visible as a known false-positive case. The complete pinned lab check is still required on every PR.
