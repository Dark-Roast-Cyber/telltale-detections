# `tdx.persistence.git_hook_change`

This candidate detects an agent setting `core.hooksPath` and a narrow co-occurrence pattern where searchable tool arguments contain both a `.git/hooks/<name>` path and a shebang marker within 400 characters. It evaluates Rule v1 `command` and `arguments`. The co-occurrence branch does not require a write operation: a match proves only that the recorded tool request contained the configuration pattern or nearby hook-path and shebang text, not that a hook was written or later executed.

The bundled regex pack has no Git-hook or `core.hooksPath` rule. Its nearest persistence rule, `persistence.shell_profile`, covers shell profiles, cron, services, and launch agents rather than repository-triggered execution. The process-chain pack also does not add agent-command coverage for Git hook configuration.

Expected false positives include explicitly requested repository bootstrap, team-managed hooks, and hook-framework installation. Read-only `git config --get core.hooksPath` is a benign confounder and is outside the pattern. The configuration branch also covers `--add` and `--replace-all` with local, global, or system scope. It requires horizontal whitespace and a value token that does not begin with a shell operator, redirection, or comment: `git config core.hooksPath || printf ...` is a query, not a write with `||` as its value. A following line is not treated as a value either. Capability limits include hook writes whose tool arguments omit content, hook programs without a shebang, writes through an unparsed script, and configuration changes expressed through unsupported command forms such as escaped line continuations. User intent and later hook execution require analyst context.

Read-only shebang inspection such as `grep '#!' .git/hooks/pre-commit` also matches the co-occurrence branch. The independently benign `detection.git_hook_shebang_query` scenario reports `false_positive` in both formats at the pinned assessment and the supplemental current-source assessment. The co-occurrence branch, severity high, score 50, and test maturity are unchanged; this finding does not justify broadening the rule to match a bare hook path.

At the pinned assessment, a direct shebang-bearing hook-file write is detected from Codex `compatible` but missed from OpenCode `upstream` (`detection.git_hook_program_write`). OpenCode's write input has separate `filePath` and `content` values; a match on a bare path would also risk alerting on reads or text that mentions a hook. Keep the miss visible until a cross-field write-specific signal is demonstrated, rather than asserting this branch works on both sources.
